# Quantum Leap R2 — issuance hardening and compatibility gates

**Date:** 2026-10-19. **Branch:** `experiment/quantum-leap-governed-offerings-r1`.
**Upstream source:** merged `origin/main` at `3ff7caee5fc89f33d90b3754d6dc518d4e914559`.

## Implemented and verified

- The original EventStore receipt code pinned `ledgerBasisDigest` outside the atomic write transaction. An intervening writer could make that asserted predecessor stale before commit.
- `EventStore.commit_command` now accepts an optional `expected_chain_digest`; the comparison occurs **inside its SQLite `BEGIN IMMEDIATE` transaction** after acquiring the write lock and before any event, aggregate, outbox or idempotency record is written. Existing callers are unaffected unless they supply a precondition.
- RuntimeService's `_commit` forwards that optional precondition. Decision-offering issuance supplies exactly the predecessor persisted in the ledger-bound receipt material. A mismatch fails closed as `LEDGER_BASIS_STALE_AT_COMMIT`.
- The new ToolBroker issuance/revocation/inspection interface is **disabled by default**. Explicit construction opt-in is necessary even for tests. This is a deployment safeguard, **not authentication**: other same-UID callers with RuntimeService access could construct their own opted-in broker. The existing actor-kind check is still not proof of human presence or secure issuer custody.
- Tests exercise two **real SQLite EventStore connections** and verify that an intervening committed event invalidates a previously observed chain basis without writing a new idempotency result. Idempotent replay leaves the chain unchanged.

## Independently demonstrated mixed-version incompatibility

- Prior baseline: `3ff7caee5fc89f33d90b3754d6dc518d4e914559`.
- The baseline's generated Python `spec.py` had SHA-256 `861d659abe08771c7d35a4677d477043b8987617d8ccdbc75356aa0ee3d995c6`.
- A **real** `DecisionOfferingIssued` envelope was generated by current RuntimeService/EventStore and validated under current generated contracts: **accepted**.
- The same envelope was tested with the baseline's actual generated Python validator, extracted from the pinned Git commit: **rejected** for unsupported `eventType`, unsupported payload discriminant and unsupported `decision_offering-` stream prefix.
- Both codebases still declare global `contractSchemaVersion = 1.0.0`. The unchanged version label therefore **does not establish reader interoperability**.

**Blocker:** No R2 event may be enabled on a shared ledger until the runtime's contract-set version negotiation, reader/writer compatibility, migration and rollback plan are implemented and tested across mixed-version instances. Full global version bump is not a trivial rename: it changes strict validators and must account for existing historical events.

## Runtime regression baseline

- Under the default macOS pytest temp-root, **both current main and the experimental branch** hit `AF_UNIX path too long` at `test_register_bot_via_authenticated_runtime`, after 96 passing tests.
- With `TMPDIR=/tmp`, baseline main passed 325 tests then failed TypeScript parity because its local generated TypeScript toolchain was not built. That is an **environment failure**, not proof of application regression.
- The combined regression suite on the merged source passed **192/192** tests, and contract drift is clean; **full CAPT runtime suite not certified**. Do not portray focused coverage as a release gate.

## Remaining authority gates

1. Authenticate a runtime-issuer credential independent of caller-supplied `actor.kind` and enforce it at the only issuance entrypoint.
2. Prove current-world freshness of the target at actual `ToolBroker` admission, not just EventStore chain currency.
3. Separate human-presence attestation from oracle/result custody; same-UID ledger hashes are insufficient.
4. Add independently custodied readback and postcondition verifier; never infer completion from receipt identity or model `finish`.
5. Complete version migration, mixed-reader tests, default-off-to-opt-in release governance, full-suite regression and rollback.
6. Keep PR #242 **draft**. No production dispatch, model inference, HumanApproval mutation, or deployed service restart was performed.

**Review verdict:** The issuance commit race is addressed at the SQLite transaction boundary. Version interoperability and authenticated issuer custody are **open blockers**.

## R3 compatibility mitigation

The R2 mixed-reader blocker for *main-ledger format exposure* is addressed in the isolated-ledger experiment: [R3 compatibility and remaining gate record](QUANTUM_LEAP_GOVERNED_OFFERING_R3_COMPAT.md). The new events are no longer written to the main EventStore when using the R3 design. Sidecar version negotiation, issuer custody, independent target readback, and full release testing are still open.
